## Решение: PyMax `maxapi-python==2.4.1`

Причины выбора:
1. **Есть сигналы о разрыве** — нужны для правила 9 (мониторинг). В PyMax это
   `@client.on_disconnect()` с `handler(exc, reconnect, delay)`, `@client.on_error()` и
   `client.is_connected`. В maxion переподключение бесконечное и без событий.
2. **Ввод SMS-кода и пароля 2FA подключаемый.** Это `SmsCodeProvider`, `PasswordProvider` или
   свой `AuthFlow`. В maxion есть только `input()`.
3. **В maxion по коду видны дефекты, ломающие сценарий S1.** Первый: откуда берётся `chat_id`.
   Второй: новое сообщение может считаться отредактированным. Подробно —
   в [stage0_research.md](stage0_research.md), раздел 4.4.
4. **Официальный бот через maxion не подходит.** Его Bot API обращается к `https://botapi.max.ru`,
   а этот домен в CLAUDE.md помечен как устаревший. Бот будет отдельным адаптером по документации dev.max.ru.

## Проверенные факты о PyMax 2.4.1 (сверено с исходниками)

- **Клиент:** `Client(phone, session_name="session.db", work_dir=".", extra_config=None,
  auth_flow=None, sms_code_provider=None, password_provider=None, app_version=..., catalog=None)`.
- **Транспорт:** TCP+TLS, хост по умолчанию — `api2.oneme.ru:443` (`ExtraConfig.host`).
- **Сессия:** SQLite-файл `work_dir/session_name`. Права 600 библиотека не выставляет — делаем сами.
- **Входящие:** `@client.on_message()`, обработчик получает `(message, client)`. Поля модели `Message`:
  `id, chat_id, sender, text, time, type, cid, attaches, status, options,
  prev_message_id, unread, mark, elements, link` и др.
  - **Телефона отправителя в сообщении нет.** Узнать его можно только отдельным запросом
    `client.get_user(id)` → `User.phone: int | None`. Вернёт ли сервер телефон — не проверено.
  - **Типа чата и признака «своё» в сообщении нет.** Тип — из `client.get_chat(chat_id).type`
    (`DIALOG` / `CHAT` / `CHANNEL`). «Своё» — сравнением `sender` с `client.me.contact.id`.
- **«Прочитано» автоматически не ставится.** Отметка — только явным `Message.read()`.
  Правило 7 соблюдается, если его не вызывать.
- **Телеметрия включена по умолчанию** (`ExtraConfig.telemetry=True`). Она имитирует действия
  пользователя. **Выключать обязательно.**
- **Отзыв токена.** При `relogin=True` (по умолчанию) библиотека удаляет сессию и заново запускает
  `auth_flow`. Стандартный SMS-вход сразу запрашивает код на номер управляющего. При `relogin=False`
  `start()`, по чтению кода, повторяет вход в цикле без паузы. **Решение для демона:** свой
  `AuthFlow`, который сразу бросает исключение. SMS-вход — только в команде `login`.
- **Ошибки входа при наличии `on_error`.** Любой зарегистрированный `on_error` помечает ошибку
  как обработанную. Тогда ошибка входа не пробрасывается из `start()`, и клиент молча закрывается.
  Демон должен сам уведомлять о таком завершении.
- **Статус «онлайн».** PING каждые 30 с с `interactive=True`. Статус переключается через
  `client.set_presence(online=False)`, применяется со следующим login/ping. Нужно ли это — решить по итогам запуска.
- **Логи:** на уровне DEBUG библиотека пишет полные кадры запросов. Держать `INFO` или выше.

## Что можно выяснить только запуском

Прототип `tools/stage0_probe.py` пишет в журнал всё нужное для этих вопросов:
1. Реальная структура события нового сообщения (raw-кадр и модель `Message`).
2. Возвращает ли `get_user` телефон отправителя, которого нет в контактах, и в каком формате.
3. Как выглядят личный чат, группа, канал и бот (`Chat.type`). Совпадает ли id личного
   чата с `my_id ^ user_id`.
4. Приходят ли в `on_message` собственные сообщения, отправленные с телефона.
5. Сколько контактов и с телефонами приходит при входе — это нужно для белого списка.
6. Не выбивает ли шлюз сессию мобильного приложения. Не пропадают ли push-уведомления на телефоне.
7. Как выглядит разрыв соединения и слёт сессии.

Полный список из 12 пунктов — в [stage0_research.md](stage0_research.md), раздел 6.

## Как запустить прототип (выполняет управляющий)

Прототип **ничего не отправляет, не отвечает и не отмечает прочитанным**. Телеметрия выключена,
автопереподключение выключено. Режим `listen` никогда не запрашивает SMS.

Запускать на своём компьютере или на VPS, **не** в облачной среде разработки.
Каталог `.session/` — это полный доступ к личному MAX: никому не передавать.

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r tools/requirements-stage0.txt

# 1. Вход (один раз): придёт SMS, код вводится в консоли
python tools/stage0_probe.py login --phone +7XXXXXXXXXX

# 2. Прослушивание: 60 минут, с запросом профиля отправителя и типа чата
python tools/stage0_probe.py listen --phone +7XXXXXXXXXX --lookup --minutes 60
```

Во время прослушивания напишите себе с другого номера личное сообщение. Добавьте сообщение в группе,
в канале и от бота, если получится. Отправьте одно сообщение со своего телефона.

Результат — файл `stage0_events.jsonl`. Телефоны, имена, тексты, ссылки и токены в нём
маскируются: остаются только структура, типы и идентификаторы. **Перед отправкой просмотрите файл.**
По этому журналу будет дописан раздел «Реальная структура событий».
