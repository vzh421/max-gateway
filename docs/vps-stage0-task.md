# Задание для сессии, работающей с VPS: запуск прототипа этапа 0 max-gateway

Это задание подготовила сессия разработки max-gateway. Прочитай его целиком, прежде чем
что-либо делать. Отвечай пользователю на русском.

## Контекст

max-gateway — будущий шлюз между личным MAX арбитражного управляющего Жалсанова В.В. и
официальным ботом. Сейчас этап 0: нужно **только посмотреть**, какие события реально
приходят в личный аккаунт MAX. Для этого есть прототип `tools/stage0_probe.py`
(библиотека `maxapi-python==2.4.1`).

Прототип **ничего не отправляет, ни на что не отвечает и не отмечает сообщения
прочитанными**. Телеметрия библиотеки выключена, автопереподключение выключено.

## Жёсткие ограничения

1. **Это основной личный номер управляющего.** Никаких отправок сообщений, никаких правок
   прототипа, которые добавляют отправку, отметку «прочитано», `set_presence`, рассылки.
2. **Вход по SMS (`login`) выполняет управляющий лично** в своём SSH-терминале: код
   приходит ему на телефон и вводится с клавиатуры. Ты `login` не запускаешь, SMS-код
   у пользователя не спрашиваешь и в чат его не принимаешь.
3. **Не трогать ai4au и всё, что уже работает на сервере**: его контейнеры, docker compose,
   nginx, базы, системный Python. Всё делается в отдельном каталоге и отдельном venv.
4. **Файл сессии (`.session/session.db`) = полный доступ к личному MAX.** Права 600,
   каталог 700. Не выводить его содержимое, не копировать, не коммитить, не отправлять
   в чат, не класть в Docker-образы. Не удалять без вопроса пользователю.
5. Не включать уровень логов DEBUG (библиотека тогда пишет в лог токен и тексты).
6. Журнал событий в git не коммитить.

## Шаги

### 1. Подготовка (делаешь ты)

```bash
python3 --version        # нужен 3.10 или новее; если старее — остановиться и сказать пользователю
mkdir -p /opt/max-gateway-stage0 && cd /opt/max-gateway-stage0
```

Получить код ветки `claude/zealous-bohr-9ocscv` репозитория `vzh421/max-gateway`:

```bash
git clone -b claude/zealous-bohr-9ocscv https://github.com/vzh421/max-gateway.git .
```

Если клонирование не удалось (приватный репозиторий, нет доступа) — не обходить,
а попросить пользователя передать файлы `tools/stage0_probe.py` и
`tools/requirements-stage0.txt` и положить их в `/opt/max-gateway-stage0/tools/`.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r tools/requirements-stage0.txt
python tools/stage0_probe.py --help     # проверка, что всё установилось
mkdir -p .session && chmod 700 .session
```

Проверь, что сервер вообще достаёт до MAX (адрес из исходников PyMax 2.4.1):

```bash
timeout 10 bash -c 'cat < /dev/null > /dev/tcp/api2.oneme.ru/443' && echo "MAX доступен" || echo "MAX НЕ доступен"
```

Если недоступен — остановиться и сообщить пользователю.

### 2. Вход (делает управляющий сам)

Выдай пользователю ровно эти команды, чтобы он выполнил их в своём SSH-терминале
(номер телефона подставляет он сам):

```bash
cd /opt/max-gateway-stage0 && . .venv/bin/activate
python tools/stage0_probe.py login --phone +7XXXXXXXXXX
```

Придёт SMS, код вводится в консоли. Если у аккаунта включён облачный пароль (2FA) —
консоль спросит и его. После входа прототип напечатает id аккаунта и сводку по
контактам и чатам (без телефонов и имён) и завершится.

Дождись, пока пользователь скажет, что вход выполнен. Затем проверь:

```bash
ls -la /opt/max-gateway-stage0/.session/     # session.db с правами -rw-------
```

### 3. Прослушивание (можешь запустить ты)

Запусти в фоне на 60 минут так, чтобы процесс пережил отключение SSH:

```bash
cd /opt/max-gateway-stage0 && . .venv/bin/activate
nohup python tools/stage0_probe.py listen --phone +7XXXXXXXXXX --lookup --minutes 60 \
  > stage0_listen.log 2>&1 &
```

(Номер — тот же, что при входе; попроси его у пользователя или пусть пользователь
запустит команду сам.)

Скажи пользователю, что в течение этого часа ему нужно:
- написать себе в личный MAX **с другого номера**, лучше двух: одного из его контактов
  и одного, которого нет в контактах;
- если возможно — получить сообщение в группе, в канале и от любого бота;
- отправить одно сообщение **со своего телефона** в любой личный чат;
- обратить внимание: не разлогинило ли MAX на его телефоне и приходят ли push-уведомления
  как обычно.

Через 1–2 минуты после запуска проверь, что процесс жив и в журнале есть запись `start`:

```bash
tail -n 5 stage0_listen.log
head -c 1500 stage0_events.jsonl
```

Если в журнале `fatal` или `error` — показать пользователю тип ошибки (без токенов)
и ничего не перезапускать в цикле: один повтор максимум, потом ждать решения.

### 4. Результат

После завершения (60 минут или остановка):

1. Покажи пользователю:
   - число строк в `stage0_events.jsonl` по видам: `start`, `raw`, `message`,
     `lookup_user`, `lookup_chat`, `disconnect`, `error`, `fatal`;
   - хвост `stage0_listen.log`.
2. Выполни проверку на утечку персональных данных и покажи результат:
   ```bash
   grep -nE '(\+?7|8)[0-9]{10}' stage0_events.jsonl | head    # должно быть пусто
   ```
   Если что-то нашлось — не передавать файл, сообщить пользователю.
3. Попроси пользователя **самого просмотреть** `stage0_events.jsonl` и передать его
   в сессию разработки max-gateway (загрузить файл в тот чат). Сам файл никуда не
   отправляй и в git не коммить.
4. Также передай пользователю для сессии разработки короткую сводку:
   - версия Python на сервере, удалось ли подключение;
   - пришёл ли `phone` в `lookup_user` для отправителя из контактов / не из контактов;
   - что пользователь заметил на телефоне (разлогин, уведомления, статус «онлайн»).
5. Каталог `/opt/max-gateway-stage0` и файл сессии **не удалять** — спросить
   пользователя. Сессия понадобится на следующих этапах.

## Если что-то пошло не так

- Не устанавливается `maxapi-python` → показать ошибку pip, ничего не обновлять
  в системе без согласия пользователя.
- MAX прислал ошибку входа / отозвал сессию → прототип сам завершится (в режиме `listen`
  SMS не запрашивается). Сообщить пользователю, повторный `login` — только по его решению.
- Любые сомнения — остановиться и спросить пользователя. Ничего не придумывать.
