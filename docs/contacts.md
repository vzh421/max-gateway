# Контакты телефона: кто должник, а кому шлюз не отвечает никогда

Контакты берутся из **Google Контактов** (только чтение) и делятся на три группы:

| Группа | Кто | Что делает шлюз |
|---|---|---|
| **должник** | номер уже в реестре должников **или** ФИО полностью совпало ровно с одним должником | перенаправляет в бот; номер добавляется в `debtor_phones` |
| **на проверке** | частичное совпадение: без отчества, инициалы, лишние слова, несколько должников-тёзок | **не отвечает**, пока вы не решите |
| **остальные** | жена, коллеги, суды, кредиторы… | **не отвечает никогда** |

Порядок защиты (правило 3):
1. ручной белый список (`whitelist add`) — не отвечать никогда, что бы ни было в контактах;
2. контакты телефона — по группе из таблицы выше;
3. адресная книга MAX (импорт при `login`) — не отвечать, если номер не определён как
   должник по контактам телефона.

Ваши решения по спорным повторная синхронизация не меняет. Контакт, удалённый из телефона,
при следующей синхронизации исчезает из классификации. Имена храним только у должников и спорных;
для остальных — только номер.

## Сопоставление ФИО

Регистр, порядок слов и «ё/е» не важны.
- **Полное совпадение** (все слова ФИО должника, в ФИО не меньше 3 слов) → должник
  автоматически. Если таких должников несколько (тёзки) → на проверку.
- **Частичное** → на проверку:
  - совпали 2 слова («Иванов Иван»);
  - фамилия и инициалы («Иванов И.И.»);
  - есть лишние слова («Иванов Иван Иванович банкрот»);
  - у должника меньше 3 слов.
- Одно общее слово (только фамилия или только имя) → не совпадение, контакт считается «остальным».

## 1. Список должников

Для сопоставления нужен список дел с ФИО должников, CSV с колонками `case_id`, `debtor_name`
и, по желанию, `case_number`. Разделитель `,` или `;`, кодировка UTF-8 или Windows-1251.

```bash
python -m gateway import-debtors debtors.csv
```

Повторная загрузка обновляет ФИО. Читать список прямо из ai4au шлюз пока не умеет: формат
ответа и пагинацию `GET /api/v1/cases/` из среды разработки проверить не удалось — нужна
схема API (`/openapi.json`) и способ авторизации.

## 2. Доступ к Google Контактам (один раз)

В [Google Cloud Console](https://console.cloud.google.com/) под своим аккаунтом:
1. Создать проект, например «max-gateway».
2. «APIs & Services» → «Library» → включить **People API**.
3. «OAuth consent screen» — тип External. Добавить свой адрес в «Test users».
4. «Credentials» → «Create credentials» → «OAuth client ID» → тип **Desktop app**.
5. Client ID и Client secret вписать в `.env`:
   ```
   GOOGLE_CLIENT_ID=…apps.googleusercontent.com
   GOOGLE_CLIENT_SECRET=…
   ```

Затем на сервере, лично:
```bash
docker compose run --rm gateway google-auth
```
Команда выдаст ссылку. Откройте её в браузере на любом устройстве и разрешите «только
чтение контактов». Браузер перейдёт на `http://127.0.0.1:8765/…` и покажет ошибку — это
нормально. Скопируйте полный адрес из адресной строки и вставьте в консоль. Ключ доступа
сохранится в `/data/google_token.json` с правами 600.

**Не проверено запуском:**
- выдаст ли Google refresh_token с этими параметрами. Если нет, команда скажет прямо;
- срок жизни доступа для приложения в режиме «Testing». По нашим сведениям Google
  ограничивает его (7 дней), но это не сверено. Если синхронизация начнёт падать с
  `invalid_grant`, повторите `google-auth` или переведите приложение в режим «In production».

## 3. Синхронизация и проверка спорных

```bash
python -m gateway contacts sync                        # вручную
python -m gateway contacts stats
python -m gateway contacts review-export review.csv    # спорные → файл для Excel
# в колонке «решение» пишете: должник / не должник
# (для «должник» с несколькими кандидатами — заполнить case_id)
python -m gateway contacts review-import review.csv
```

Сервис синхронизирует контакты сам раз в `CONTACTS_SYNC_HOURS` (по умолчанию 24;
`0` — только вручную). О новых спорных и о сбоях синхронизации приходят уведомления.

В файле проверки — полные номера и имена из ваших контактов. Храните его только у себя.
