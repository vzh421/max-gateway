# Контакты телефона: кто должник, а кому шлюз не отвечает никогда

Контакты загружаются из **CSV-экспорта Google Контактов** и делятся на три группы:

| Группа | Кто | Что делает шлюз |
|---|---|---|
| **должник** | номер уже в реестре должников **или** ФИО полностью совпало ровно с одним должником | перенаправляет в бот; номер добавляется в `debtor_phones` |
| **на проверке** | частичное совпадение: без отчества, инициалы, лишние слова, несколько должников-тёзок | **не отвечает**, пока вы не решите |
| **остальные** | жена, коллеги, суды, кредиторы… | **не отвечает никогда** |

Порядок защиты (правило 3):
1. ручной белый список (`whitelist add`) — не отвечать никогда, что бы ни было в контактах;
2. контакты телефона — по группе из таблицы выше;
3. адресная книга MAX (импорт при `login`) — не отвечать, если номер не определён как
   должник по контактам телефона.

Ваши решения по спорным повторная загрузка не меняет. Имена храним только у должников и спорных;
для остальных — только номер.

## Сопоставление ФИО

Регистр, порядок слов и «ё/е» не важны. Фамилия — первое слово ФИО должника
(в `case-map.json` — «Фамилия Имя Отчество»).
- **Полное совпадение** (все слова ФИО должника, в ФИО не меньше 3 слов) → должник
  автоматически. Если таких должников несколько (тёзки) или есть ещё частичные
  совпадения с другими должниками → на проверку.
- **Частичное** — совпала **фамилия** и ещё имя или инициалы («Иванов Иван»,
  «Иван Иванов», «Иванов И.И.», «Иванов Иван Иванович банкрот») → на проверку.
- Совпали только имя и отчество при другой фамилии, или одно слово → не совпадение.

На реальных данных (1992 номера, 1071 должник-физлицо): 44 должника автоматически,
94 на проверку (у 92 — один кандидат), остальные 1854. Без требования фамилии спорных было 258.
Управляющий проверил все 94 — все оказались должниками (итого 138 номеров должников).

## 1. Список должников

Основной источник — **`case-map.json`** (карта дел, version 1):
```bash
python -m gateway import-debtors case-map.json
```
Берутся только банкротства физлиц (`type: BFL`, путь `_БФЛ/<ФИО>`); юрлица и прочие дела
пропускаются. **Идентификатор дела — номер дела** (`А40-1234/2025`, ключ в `cases`):
id ai4au в карте нет. Повторная загрузка обновляет ФИО.

Запасной вариант — CSV с колонками `case_id`, `debtor_name`, `case_number`.

Сверка с ai4au (`GET /api/v1/cases/`) — после открытия доступа: нужен токен на чтение и
сетевой доступ к ai4au.ru, а формат ответа и пагинацию надо сверить по `/openapi.json`.

## 2. Выгрузка контактов из Google

contacts.google.com → «Экспортировать» → формат **Google CSV** → файл `contacts.csv`.

Формат сверен по реальному экспорту:
- ФИО — колонки `First Name` / `Middle Name` / `Last Name` (а также `File As`, если заполнена);
- телефоны — колонки `Phone 1…N - Value`, несколько номеров в ячейке через `:::`.

Если колонок телефонов в файле нет, шлюз ничего не загрузит и покажет заголовки.
Номера не РФ и короткие (городские, служебные) пропускаются — им шлюз и так не отвечает:
телефон не распознан, значит собеседник «неизвестный».

Файл содержит все ваши контакты. Загрузите его на сервер, импортируйте и **удалите**.

## 3. Загрузка и проверка спорных

```bash
python -m gateway contacts import contacts.csv         # добавить/обновить
python -m gateway contacts import contacts.csv --replace   # файл — ПОЛНЫЙ список: номера, которых
                                                           # в нём нет, перестают быть «контактами»
python -m gateway contacts stats
python -m gateway contacts review-export review.csv    # спорные → файл для Excel
# в колонке «решение» пишете: должник / не должник
# «должник» с несколькими кандидатами: case_id = номер дела; пусто — все кандидаты
#   (дело должник выберет в боте)
# ключ строки — телефон: файл можно заполнить по одной базе и загрузить в другую
python -m gateway contacts review-import review.csv
```

**Порядок:** сначала список должников (раздел 1), потом контакты. Контакты сравниваются
со списком должников на момент загрузки. После обновления списка должников загрузите
контакты ещё раз: автоматические решения пересчитаются, ваши останутся.

Новые контакты в телефоне шлюз увидит только после новой выгрузки и загрузки. Пока новый
контакт не загружен, он защищён только адресной книгой MAX: если она его содержит, ответа не будет.
Без `--replace` частичный файл (например, одна группа) ни с кого защиту не снимает.

В файле проверки — полные номера и имена из ваших контактов. Храните его только у себя.
