# Выгрузка переписки с должниками для анализа

Цель — понять по реальной переписке в личном MAX, **о чём пишут должники**, и на этой основе
спроектировать ответы бота: что бот может отвечать сам, а что — только черновиком управляющему.

## Что делает `history-export`

```bash
docker compose stop gateway     # к MAX должен быть подключён только один процесс
docker compose run --rm -v "$PWD/out:/out" gateway history-export /out/history.jsonl \
    --manager-name "Жалсанов Виталий Викторович"
docker compose start gateway
```

1. Подключается к MAX по существующей сессии. SMS не запрашивает.
2. Проходит по списку чатов (`fetch_chats`) и берёт телефоны собеседников пакетами (`get_users`).
3. Для личных чатов с номерами из реестра должников выгружает до `--per-chat` (200)
   последних сообщений (`fetch_history`). Чатов не больше `--max-chats` (300).
4. Между запросами — пауза 2 с.

**Только чтение.** Отправок нет. Отметка «прочитано» в коде не вызывается. Поиск по номеру
телефона не используется. Тест проверяет, что в модуле нет этих вызовов.

**Не проверено запуском:**
- как сервер листает список чатов;
- не отмечает ли сервер чат прочитанным сам в ответ на запрос истории.

Во время выгрузки проверьте на телефоне, не пропали ли непрочитанные.

## Обезличивание

- Чаты получают псевдонимы `D001`, `D002`…; даты — без времени.
- Маскируются телефоны, ИНН, СНИЛС, e-mail, номера карт и счетов, паспорт.
- ФИО должника по делу → `[ДОЛЖНИК]`, ФИО управляющего → `[УПРАВЛЯЮЩИЙ]`, включая падежные
  формы по основе слова.
- Вложения — только тип (PHOTO, FILE…).
- **Другие имена, адреса, суммы и подробности в тексте остаются.** Файл содержит
  персональные данные: хранить только у управляющего, после анализа удалить.

## Что будет в анализе (`docs/debtor-needs.md`)

По каждой теме обращений:
- частота (сколько чатов и сообщений);
- типичные формулировки (обезличенно);
- что обычно отвечал управляющий;
- **какие данные нужны для ответа** и есть ли они в ai4au (статус дела, заседания,
  документы, расходы…);
- **класс автономности:**
  - **А** — бот отвечает сам: справочное, по данным ai4au, без юридической оценки;
  - **Б** — бот отвечает шаблоном и зовёт управляющего;
  - **В** — только черновик на одобрение (юридические вопросы, CLAUDE.md, S4) или сразу управляющему.

Итог — спецификация для сессии бота: список интентов, шаблоны ответов (плейсхолдеры,
тексты утверждает управляющий), нужные поля ai4au, правила эскалации.

**Ограничение CLAUDE.md:** ответы на юридические вопросы — только черновик на одобрение
управляющего, автоматической отправки нет. Анализ покажет, какую долю обращений бот сможет
закрыть сам (класс А), не нарушая этого правила.
