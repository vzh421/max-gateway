# Этап 2 — распознавание должника и перенаправление в бот

Статус: **реализовано и покрыто тестами** (158 тестов, SQLite и PostgreSQL 16). С реальным
MAX не запускалось. Режим по умолчанию — dry-run, тексты — плейсхолдеры `[НЕ УТВЕРЖДЕНО]`.

Бот — в отдельной сессии. Контракт между шлюзом и ботом: [bot-integration.md](bot-integration.md).

## Сценарий (gateway/core.py)

Для каждого входящего в личный MAX:

1. **Журнал** — всегда, первым делом. Повтор того же события → выход, второго ответа нет.
2. **Фильтры** (правило 4). Пропускаются:
   - свои сообщения (они приходят с телефона — журнал этапа 0);
   - каналы (`chat_id < 0`, тип `CHANNEL`);
   - группы (`get_chat` → не `DIALOG`);
   - боты (`User.options` ∋ `BOT`: чат с ботом тоже `DIALOG`).
3. **Учёт собеседника** в `personal_chats`: id MAX, телефон, дело, первое и последнее обращение.
4. **Белый список** (правило 3) → без ответа. Если номер совпал с должником — уведомление
   управляющему.
5. **Поиск по `debtor_phones`**:
   - не найден (или телефон скрыт) → уведомление «пишет неизвестный» (один раз на чат), без ответа;
   - одно дело → токен на это дело;
   - несколько дел → токен с `candidate_case_ids`, выбор в боте.
6. **Перенаправление** (правило 5):

   | Обращение | Действие |
   |---|---|
   | первое | `REDIRECT_FIRST_TEMPLATE` со ссылкой |
   | повторное, прошло < 24 ч | тишина |
   | повторное, прошло ≥ 24 ч, напоминаний < 3 | `REDIRECT_REMINDER_TEMPLATE` с той же ссылкой |
   | после 3 напоминаний | тишина + **одно** уведомление управляющему |

   Счёт идёт в окне `REDIRECT_WINDOW_DAYS` (30 дней). Если токен уже погашен ботом —
   ссылка на бота без `start`.
7. **Отправка** — только через `SendGuard`, в фоне: задержка 20–90 с не тормозит приём.
   SendGuard независимо от core перепроверяет лимиты на чат, лимит в час, kill switch,
   мониторинг, неутверждённый текст и dry-run.

Ошибка при обработке (например, MAX не ответил на `get_chat`) не останавливает приём:
сообщение уже в журнале, управляющему уходит уведомление.

## Ссылка в тексте

PyMax разбирает исходящий текст как markdown и **вырезает `_` даже внутри адреса**
(`https://max.ru/test_bot` → `testbot`). Экранирование `\_` не работает — проверено на
`Formatter` 2.4.1. Поэтому:
- ссылка вставляется в форме `[url](url)` — адрес сохраняется целиком как элемент LINK
  (тест `test_link_survives_pymax_markdown`);
- токен — 32 символа `[0-9a-f]` (`secrets.token_hex(16)`), без `_`.

**Не проверено:** как MAX отображает такую ссылку у получателя. В журнале этапа 0
входящие LINK-элементы были, поэтому формат MAX знаком. Проверить на первом боевом тесте.

Тексты шаблонов тоже разбираются как markdown: `*`, `_`, `~`, `` ` `` меняют начертание.

## Токены (gateway/tokens.py)

- Один действующий токен на чат переиспользуется во всех напоминаниях. Новый выпускается,
  если до истечения старого меньше часа.
- Срок — `TOKEN_TTL_DAYS` (14). Гашение атомарное (условный UPDATE), повтор тем же
  пользователем бота идемпотентен, другим — `409`, истёкший — `410`.

## Уведомления (gateway/notify.py)

- Доставка — POST на `BOT_NOTIFY_URL` (эндпоинт бота). Если он не задан — в лог.
- Срочные (сбой MAX, отправки остановлены) — сразу. Остальные — сводкой раз в
  `NOTIFY_DIGEST_MINUTES`.
- Штатные блокировки (интервал, лимит на чат) в уведомления не попадают.
- Недоставленное уведомление пишется в лог, обработка не прерывается.

## Надёжность отправки

- Остановка сервиса во время задержки → отправка отменяется (`cancelled`) и в лимиты не
  считается.
- Аварийная остановка посреди отправки → при старте запись `pending` помечается `unknown` и
  **считается отправленной**: лучше не ответить, чем ответить дважды.

## Что осталось

1. Утвердить тексты `REDIRECT_FIRST_TEMPLATE` и `REDIRECT_REMINDER_TEMPLATE` (сейчас плейсхолдеры).
2. Сессия бота: реализовать API из `bot-integration.md` на своей стороне (гашение токенов,
   эндпоинт уведомлений), сообщить `BOT_USERNAME`, адрес и ключи.
3. Импортировать телефоны должников (`import-phones`).
4. Развернуть и прогнать в dry-run. Затем — по явному решению управляющего — боевой
   тест на 5–10 своих должниках.
