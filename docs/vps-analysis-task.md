# Задание для сессии VPS: загрузка данных, выгрузка переписки и анализ потребностей должников

Задание подготовила сессия разработки max-gateway. Прочитай его целиком. Отвечай пользователю
на русском. Сначала выполни `docs/vps-stage1-deploy.md` (развёртывание и вход в MAX), если это
ещё не сделано.

## Правила

1. **Код не менять.** Ни в `/opt/max-gateway`, ни в git. Если что-то не работает — остановиться
   и описать пользователю (он передаст в сессию разработки). Так не будет затирания правок.
2. **Ничего не отправлять с личного MAX.** `DRY_RUN=true`, выгрузка — только чтение.
3. Файлы с персональными данными (архив, `history.jsonl`, файлы проверки) — только в
   `/opt/max-gateway/private/` с правами 700/600, не выводить содержимое в чат, не коммитить,
   после работы удалить (кроме итогового анализа, в котором ПДн нет).
4. Сомнения — спросить пользователя. Ничего не придумывать.

## 1. Данные от пользователя

Пользователь передаст архив `max-gateway-data.zip`: `case-map.json` (карта дел),
`contacts.csv` (контакты телефона), `review-decided.csv` (его решения по 94 спорным
контактам). Порядок загрузки важен:

```bash
cd /opt/max-gateway && mkdir -p private && chmod 700 private
# положить архив в private/ и распаковать
cd private && python3 -m zipfile -e max-gateway-data.zip . && sha256sum -c SHA256SUMS && chmod 600 * && cd ..
M='-v /opt/max-gateway/private:/private:ro'
docker compose run --rm $M gateway import-debtors /private/case-map.json
docker compose run --rm $M gateway contacts import /private/contacts.csv
docker compose run --rm $M gateway contacts review-import /private/review-decided.csv
docker compose run --rm gateway contacts stats
```

Ожидаемо (так получилось при проверке в сессии разработки): должников 1071 загружено
(21 не физлица пропущено); контактов 1992 номера; после решений — `debtor: 138`,
`other: 1854`, `решено_управляющим: 94`. Если числа другие — сообщить пользователю.

## 2. Выгрузка переписки

```bash
docker compose stop gateway
docker compose run --rm -v /opt/max-gateway/private:/out gateway history-export /out/history.jsonl \
    --manager-name "Жалсанов Виталий Викторович"
docker compose start gateway
```
Передай пользователю итоговую строку. Попроси проверить на телефоне, не пропали ли
непрочитанные (не проверено, отмечает ли сервер чаты прочитанными при чтении истории).

Формат строки `history.jsonl`: `{"chat": "D001", "date": "YYYY-MM-DD", "role": "должник"|"управляющий",
"text": "...", "attachments": ["PHOTO", ...]}`. Телефоны, ИНН, СНИЛС, e-mail, карты, счета, паспорт
и ФИО должника/управляющего уже замаскированы, но другие имена, адреса и суммы могут остаться.

## 3. Анализ (делаешь ты, на сервере)

Прочитай `history.jsonl` целиком. Цель — понять, **что нужно должникам**, чтобы спроектировать
ответы бота (он делается в отдельной сессии). Ничего не придумывать: каждая тема и каждая цифра —
только из файла.

1. **Темы обращений.** Разметь каждое сообщение должника одной или несколькими темами. Список
   тем выведи из данных (не подгоняй под заранее придуманный). Для каждой темы посчитай:
   число чатов и сообщений.
2. **Для каждой темы:**
   - 2–4 типичные формулировки — перефразированные, **без имён, адресов, сумм, дат рождения**;
   - что обычно отвечал управляющий (обобщённо) и как быстро (по датам, если видно);
   - какие данные нужны для ответа: статус процедуры, дата заседания, список документов,
     реквизиты, суммы, этап реализации имущества и т. п.; где они могут быть (ai4au / у
     управляющего / нигде);
   - **класс автономности**:
     - **А** — бот может отвечать сам: справочное или по данным ai4au, без юридической оценки;
     - **Б** — бот отвечает шаблоном («принято, управляющий ответит») и передаёт управляющему;
     - **В** — только черновик на одобрение управляющего или сразу управляющему: юридические
       вопросы, спорные ситуации, жалобы, эмоционально острые сообщения. Правило проекта
       (CLAUDE.md, S4): ответы на юридические вопросы автоматически не отправляются.
3. **Вложения:** какие документы должники присылают (по типам и по контексту сообщений).
4. **Итог:** доля обращений по классам А/Б/В; топ-10 тем; что нужно от ai4au для класса А;
   какие шаблоны ответов нужны (текст — плейсхолдер `[НЕ УТВЕРЖДЕНО]`, утверждает управляющий).
5. **Проверка на ПДн:** в итоговом документе не должно быть имён, телефонов, адресов, сумм,
   номеров дел, дат рождения. Перед передачей перечитай его.

Результат оформи в `debtor-needs.md` (markdown, по разделам выше) в `/opt/max-gateway/private/`
и отдай пользователю. **В git не коммить** — пользователь передаст файл в сессию разработки,
она положит его в `docs/` и в задание для сессии бота.

## 4. Уборка

После того как пользователь подтвердит, что получил `debtor-needs.md`:
```bash
shred -u /opt/max-gateway/private/history.jsonl /opt/max-gateway/private/contacts.csv \
  /opt/max-gateway/private/review-decided.csv /opt/max-gateway/private/max-gateway-data.zip 2>/dev/null
```
`case-map.json` удалять только с согласия пользователя (может понадобиться при обновлении списка должников).
